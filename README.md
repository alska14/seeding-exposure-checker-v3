# 시딩 노출 확인 (3차: 웹 버전)

시딩(협찬) 리스트를 올리면 유튜버가 영상에서 제품을 노출했는지 1차로 골라주는 웹 서비스입니다.
사용자가 자기 YouTube·OpenAI API 키를 입력해서 쓰며, 키는 서버에 저장하지 않습니다.
설계는 `docs/superpowers/specs/2026-11-04-seeding-web-design.md`에 있습니다.

## 로컬 실행
```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt -r requirements-web.txt -r requirements-dev.txt
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```
브라우저에서 http://127.0.0.1:8000 을 엽니다. 영상 분석에는 ffmpeg가 필요합니다.

## API 키 넣는 방법
**키는 환경변수가 아니라 화면에서 입력합니다.** 서버는 키를 읽지도 저장하지도 않고, 입력한 키는 그 작업 한 건을 실행하는 동안만 쓰입니다.
1. 서버를 켭니다(위 "로컬 실행").
2. 브라우저에서 새 작업을 만들고 엑셀을 올립니다.
3. ① 준비 분석 칸에 YouTube 키, ② 영상 분석·③ 재검증 칸에 OpenAI 키를 붙여넣고 시작합니다. 칸은 제출하면 바로 비워집니다.
- 키 발급: YouTube Data API v3(Google Cloud Console), OpenAI API 키(platform.openai.com).
- 서버 환경변수는 아래 표의 설정값뿐입니다. 키 이름(`YOUTUBE_API_KEY` 등)을 서버 환경에 넣어도 엔진에는 전달되지 않습니다.

## 쉽게 시작하기 (업종 프리셋·입력 방식·견적)
- **업종 프리셋:** 새 작업에서 업종을 고르면 제목 키워드·수집 기간 같은 임시값이 채워지고 모두 고칠 수 있습니다. 실제 데이터로 검증된 업종은 패션뿐입니다. 다른 업종은 영상 분석 기준이 "옷 착용"이라 정확도가 검증되지 않았고, 화면에 안내하며 확인란을 체크해야 영상 분석을 시작할 수 있습니다(제목·설명란·댓글·링크 점검은 제한 없음).
- **입력 방식:** ① 엑셀 템플릿 내려받아 채우기 ② 열 순서가 다른 엑셀을 그대로 올리면 열을 자동으로 찾고 고칠 수 있음 ③ 채널 주소를 한 줄에 하나씩 붙여넣기(발송일이 없으면 시작일·수집 기간을 지정). 한 작업에 채널 최대 300곳, 한 유튜버당 한 줄.
- **견적:** 작업 화면의 "견적(추정)"이 예상 비용·소요 시간·YouTube 쿼터를 보여줍니다. 준비 분석 전에는 채널 수로 대략 계산하고, 후에는 실제 수집 결과로 다시 계산하며 비용 상한을 바꾸면 즉시 갱신됩니다. 기본값은 패션 시딩 93명 1회 실행의 실측(영상당 약 $0.03, 약 5초, 댓글은 영상당 쿼터 1)이고, 이 서버에서 작업이 끝날 때마다 단계별 소요 시간을 기록해 영상당 시간 추정을 보정합니다. 준비 분석 시간·무료 재검증 시간은 아직 측정되지 않아 표시하지 않습니다.

## 영상 분석은 내 PC에서 (PC 도우미)
YouTube는 클라우드 서버 IP의 영상 다운로드를 봇으로 보고 막습니다(Railway에서 `Sign in to confirm you're not a bot`으로 확인). 그래서 서버는 영상 분석을 하지 않고(`SERVER_VIDEO=0`, 기본값), 이 단계만 내 컴퓨터에서 실행합니다. 수집·댓글·링크 점검·판정 보드는 그대로 웹에서 합니다.
1. 준비 분석 후 ② 칸에서 비용 상한을 정하고 **분석 패키지(zip)** 를 받습니다. 상한에 맞춰 채널당 분석할 영상 수가 정해집니다.
2. 압축을 풀고 `읽어보세요.txt`대로 준비한 뒤 `실행.bat`을 실행합니다(Python 3.10+, ffmpeg 필요). **OpenAI 키는 그 창에서 입력**하고 어디에도 저장되지 않습니다.
3. 끝나면 생기는 `result.json`을 ② 칸의 **결과 올리기**로 올립니다. 서버가 알려진 필드만 남기고 설정 지문이 같은 결과만 받아 판정에 반영합니다.
- 패키지에는 API 키와 작업 토큰이 들어 있지 않고, 채널 목록과 수집 결과가 들어 있으니 끝나면 폴더를 지우세요.
- 서버를 로컬에서 쓸 때는 `SERVER_VIDEO=1`로 서버가 직접 영상 분석을 하게 할 수 있습니다(① 집 IP에서는 다운로드가 됩니다).

## 배포 진단
`DIAG_TOKEN` 환경변수를 정한 서버에서만 `GET /api/diag/download`(헤더 `X-Diag-Token`)가 열리고, 고정된 공개 영상 하나로 이 서버에서 영상 다운로드·프레임 추출이 되는지 확인합니다. 설정하지 않으면 404입니다. 시험이 끝나면 변수를 지우세요.

## 재검증(미확인 채널)
③ 칸의 "계획 보기"는 아무것도 호출하지 않고 대상 수·쿼터·예상 비용만 보여줍니다. "재검증 시작"은 댓글 재검토, 표기 변형, 설명란 링크, 분석 서술 재검색을 실행하고, 비용 상한을 적으면 안 본 영상도 분석합니다. 한 번에 쓰는 YouTube 쿼터와 링크 수는 `MAX_COMMENT_QUOTA`, `MAX_LINKS`로 제한합니다. 결과로 바뀐 판정은 보드에 반영됩니다.

## 테스트
```bash
.venv/Scripts/python -m pytest -q
```
외부 API 없이 가짜 엔진으로 업로드 → 준비 분석 → 영상 분석 → 재검증 → 삭제 흐름과,
**키가 DB·로그·파일·응답에 남지 않는지**를 검사합니다.

## 설정 (환경변수)
| 이름 | 기본값 | 뜻 |
| --- | --- | --- |
| DATA_DIR | ./data | 작업 데이터와 DB 위치 |
| MAX_JOBS | 1 | 동시에 도는 작업 수 |
| MAX_CAP_USD | 50 | 사용자가 정할 수 있는 비용 상한의 최댓값 |
| JOB_TTL_DAYS | 7 | 작업 데이터 보관 일수 |
| MAX_COMMENT_QUOTA | 2000 | 재검증 한 번에 쓸 YouTube 쿼터 상한 |
| MAX_LINKS | 300 | 재검증 한 번에 따라갈 설명란 링크 수 |
| SERVER_VIDEO | 0 | 1이면 서버가 영상 다운로드·분석을 직접 함(클라우드에서는 막힘). 0이면 PC 도우미 |
| DIAG_TOKEN | (없음) | 설정하면 배포 진단 엔드포인트가 열림 |
| REQUIRE_HTTPS | 0 | 1이면 HTTPS가 아닌 요청 거부(운영에서 켬) |

## 배포
`Dockerfile`이 있습니다(ffmpeg 포함). 아직 실제 배포와 도커 빌드는 해보지 않았습니다.
**배포 전에 확인할 것:** 클라우드 서버 IP에서 영상 다운로드(yt-dlp)가 막히는지.

## 구조
- `seeding_checker.py`: 기존 분석 엔진(명령줄·캐시 형식 유지). 웹 서버가 작업 폴더에서 별도 프로세스로 실행합니다.
- `app/`: FastAPI 서버(업로드, 작업 실행, 키 가리기, 비용 상한, 확인 기록)
- `web/`: 화면
