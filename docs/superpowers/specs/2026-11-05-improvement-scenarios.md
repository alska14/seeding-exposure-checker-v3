# 개선 시나리오: 누구나 원하는 정보를 쉽게 모으는 유튜브 크롤링 도구

작성일 2026-11-05 · 상태: 제안(승인 전). 앞선 설계서(`2026-11-04-seeding-web-design.md`)에 이어 쓴다.

## 1. 지금 부족한 점 (직접 써보고 알게 된 것)

| 부족한 점 | 왜 문제인가 |
| --- | --- |
| 입력이 시딩 엑셀 전용이다 (3행부터, 열 순서 고정, 발송일 필요) | 채널 주소만 있는 사람, 다른 양식의 엑셀을 가진 사람은 시작도 못 한다 |
| 의류 착용 확인만 된다 (영상 분석 프롬프트가 "입었는가" 전제) | 화장품·음식·전자기기 같은 업종은 쓸 수 없다 |
| 설정이 어렵다 (브랜드·상품·제목 키워드를 직접 다 적어야 함) | 처음 쓰는 사람이 무엇을 넣어야 하는지 모른다 |
| 비용 예상이 "영상 수 × $0.03" 한 줄뿐이고 시간·쿼터 예상이 없다 | 돌리기 전에 얼마나 걸리고 얼마 드는지 판단하기 어렵다 |
| 결과 항목이 고정이다 (판정·근거·링크) | 조회수, 업로드일처럼 원하는 정보를 골라 받을 수 없다 |
| 작업 주소를 잃어버리면 다시 못 연다 | 일주일 안에 돌아와도 결과를 잃을 수 있다 |

## 2. 사용 시나리오

**S1. 처음 쓰는 마케터 (가장 중요)**
1. 업종을 고른다(패션, 뷰티, 식품…). 브랜드명만 넣으면 나머지 키워드·제목 키워드·검색 규칙이 임시값으로 채워진다.
2. 엑셀 템플릿을 내려받아 채널만 채우거나, 채널 주소를 그냥 붙여넣는다.
3. **견적 패널**이 "대상 채널 N곳, 영상 약 M개, 예상 비용 약 $X, 소요 약 N분, YouTube 쿼터 N / 10,000"을 보여준다.
4. 비용 상한을 정하고 시작한다. 진행률과 남은 시간이 나온다.
5. 보드에서 결과를 보고, 필요한 열만 골라 엑셀로 받는다.

**S2. 채널 목록만 가진 사람**: 발송일이 없으므로 "최근 N일" 또는 기간을 직접 지정해서 영상을 모은다.

**S3. 키워드 모니터링**: 채널을 모르는 상태에서 "브랜드명" 같은 검색어로 영상을 찾고, 그 영상의 채널·제목·조회수를 표로 받는다.

**S4. 다시 찾아오기**: 같은 브라우저에서는 최근 작업 주소를 기억해(키는 제외) 목록으로 보여준다. 이메일·로그인은 만들지 않는다.

## 3. 기능 제안과 우선순위

| 순위 | 기능 | 설명 | 검증 필요 |
| --- | --- | --- | --- |
| P1 | 견적 패널 | 준비 분석이 끝나면 비용·시간·쿼터 예상 표시. 아래 4장 | 실측 보정 필요 |
| P1 | 업종 프리셋 | 업종 선택 → 키워드 등 임시값 자동 입력, 사용자가 수정. 아래 5장 | 패션만 실데이터로 검증됨 |
| P1 | 입력 간소화 | 템플릿 엑셀 다운로드, 채널 주소 붙여넣기, 열 이름 자동 인식·매핑 화면, 발송일 없으면 기간 지정 | 쉬움 |
| P2 | 수집·내보내기 항목 선택 | 조회수·좋아요·댓글 수(영상 정보에 같이 오므로 쿼터 추가 거의 없음), 업로드일, 태그, 설명란 링크 등을 골라 엑셀/CSV로 | 보통 |
| P2 | 키워드 모니터링 모드 | 검색 API는 요청 1번에 쿼터 100이라 상한을 둔다 | 쿼터 부담 큼 |
| P3 | 근거 프레임 미리보기 | 판정 근거 장면을 보드에서 바로 보기. 저장 용량·개인정보 검토 필요 | 보통 |
| 제외 | 로그인, 결제, 예약 실행, 알림 | 이번 범위 밖 | |

## 4. 견적 패널 (예상 비용·시간)

**표시 형식**: `예상 비용 약 $X (상한 $Y) · 소요 약 N분 · YouTube 쿼터 약 Q / 10,000`. 정확하지 않은 숫자는 "약"과 범위로 쓴다.

**지금까지 실제로 잰 값 (패션 시딩 93명 1회 실행 기준 — 표본 1건)**

| 항목 | 실측 | 비고 |
| --- | --- | --- |
| 영상 분석 비용 | 영상 669개에 약 $21.5 → **영상당 약 $0.03** | 1차 판단 + 반박 검수 포함, 정가 기준 |
| 영상 분석 시간 | 54분 / 669개 → **영상당 약 5초** (동시 2개 실행 기준) | 다운로드 속도·영상 길이에 따라 달라짐 |
| 댓글 재검토 쿼터 | **영상당 1** | 예: 1,150개 영상 → 쿼터 약 1,150 |
| 채널·영상 수집 쿼터, 준비 분석 시간, 링크 추적 시간 | **미측정** | 아래 보정 방법으로 측정 |
| 자막 검색 | 측정 불가 (이 PC IP 차단) | 서버 환경에서 따로 확인 |

**보정 방법**: 엔진이 단계마다 걸린 시간, 쿼터, 토큰을 `work/metrics.json`에 기록한다. 견적은 처음엔 위 실측값을 쓰고, 같은 서버에서 작업이 쌓이면 최근 실측 평균으로 바꾼다. 표시는 항상 "추정"이라고 쓴다.

**계산식 (초안)**
- 영상 분석 비용 = 분석할 영상 수 × 영상당 단가(기본 $0.03)
- 영상 분석 시간 = 분석할 영상 수 × 영상당 초(기본 5초, 동시 작업 수에 반비례)
- 쿼터 = 채널 수 × (채널당 수집 비용: 측정 후 확정) + 댓글 받을 영상 수

## 5. 업종 프리셋 (임시값)

프리셋이 채우는 것: 브랜드·상품 키워드 예시, **제목 키워드**(노출 가능성 높은 영상을 먼저 보기 위한 단어), **광고 표기 키워드**, **영상에서 볼 것**(영상 분석 설명), 기본 수집 기간. 모두 사용자가 고칠 수 있다.

| 업종 | 제목 키워드(임시) | 영상에서 볼 것(임시) | 검증 상태 |
| --- | --- | --- | --- |
| 패션·의류 | 룩북, 코디, 착장, 하울, ootd, grwm | 착용한 옷의 프린트·로고·색 | **실데이터 검증(93명)** |
| 뷰티·화장품 | 리뷰, 데일리 메이크업, 하울, 파우치, 루틴, grwm | 사용하는 제품 용기·패키지·로고 | 미검증 (프롬프트 수정 필요) |
| 식품·음료 | 먹방, 리뷰, 맛집, 레시피, 편의점, 언박싱 | 먹거나 보여주는 제품 포장·로고 | 미검증 |
| 전자기기·IT | 리뷰, 언박싱, 사용기, 비교, 세팅, 데스크 | 기기 외형·로고·화면 | 미검증 |
| 게임·앱 | 플레이, 후기, 공략, 추천, 체험 | 화면 속 앱·게임 UI·로고 | 미검증 |
| 여행·숙박 | 브이로그, 여행, 숙소, 호텔, 후기 | 숙소·장소 간판·로고 | 미검증 |
| 생활·인테리어 | 룸투어, 인테리어, 집들이, 추천템, 언박싱 | 집 안 제품·가구 외형·로고 | 미검증 |

**정직하게 알릴 것**: 현재 영상 분석 프롬프트는 "옷을 입었는가"에 맞춰져 있다. 패션 외 업종은 제목·설명란·댓글·링크 점검(텍스트 기반)은 바로 쓸 수 있지만, 영상 분석은 업종별 프롬프트를 만들고 정답 영상으로 검증해야 한다. 그 전까지는 화면에 "이 업종의 영상 분석은 아직 검증되지 않았습니다"를 표시한다.

## 6. 만드는 순서와 완료 기준

1. 견적 패널와 단계별 실측 기록 — 준비 분석 후 비용·시간·쿼터가 화면에 나온다. 테스트: 가짜 데이터로 계산식 검증.
2. 업종 프리셋 — 선택하면 칸이 채워지고 수정할 수 있다. 비패션은 미검증 안내가 보인다.
3. 입력 간소화 — 템플릿 다운로드, 주소 붙여넣기, 열 매핑, 기간 지정.
4. 항목 선택 내보내기 — 선택한 열만 CSV/엑셀에 들어간다.
5. 키워드 모니터링 — 쿼터 상한과 함께.

각 단계는 pytest와 브라우저 확인을 거친다. 실제 키로 도는 시험은 사용자가 키를 직접 입력해서 한다.
