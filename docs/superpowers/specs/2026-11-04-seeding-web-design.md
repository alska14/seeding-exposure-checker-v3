# 시딩 노출 확인 웹 (3차) 설계서

작성일 2026-11-04 · 상태: 설계 승인 후 구현 중

## 1. 목적과 범위

시딩(협찬) 리스트를 가진 누구나 웹에서 엑셀을 올리고, 자기 API 키로 분석을 돌려, 채널별 노출 판정 보드를 받고, 담당자 확인 결과를 기록할 수 있게 한다.
1차(자동 선별과 보드)와 2차(미확인 재검증)의 과정을 한 서비스로 합친다.

**결정된 것**
- 사용자는 자기 YouTube·OpenAI API 키를 입력한다. 비용은 사용자가 낸다.
- 서버는 파이썬 FastAPI 하나. 같은 서버가 화면도 제공한다. 배포 후보는 Railway(Docker).
- 분석 엔진은 기존 `seeding_checker.py` 명령줄을 그대로 쓴다(아래 3장).
- 계정과 로그인은 없다. 작업 주소의 긴 토큰을 아는 사람만 결과를 연다.

**이번에 하지 않는 것**
- 유튜브 외 플랫폼, 회원가입·결제, 여러 브랜드 관리.
- API 키를 넣은 실제 분석 실행 테스트(환경 구축까지만 한다).
- 실제 배포(Railway). 영상 다운로드가 서버 IP에서 막히는지는 배포 전 별도 시험이 필요하다.

## 2. 사용자 흐름

1. 새 작업: 시딩 리스트(xlsx), 브랜드 키워드, 상품 키워드, (선택) 상품 참고 사진을 입력한다.
2. 키 입력: YouTube 키(필수), OpenAI 키(영상 분석에 필요). 키 검증 버튼은 두지 않는다(쿼터 소모 방지).
3. **1단계 준비 분석**: parse → collect → screen. YouTube 쿼터만 쓰고 OpenAI 비용은 없다.
4. **비용 확인**: 준비 분석 결과로 영상 분석 대상 수와 예상 비용을 보여주고, 사용자가 상한(USD)을 정한다.
5. **2단계 영상 분석**: watch → report. 상한을 넘기지 않게 채널당 분석 영상 수를 줄여서 돌린다.
6. 보드: 판정 필터, 검색, 근거 영상 링크, 확인 결과 기록(서버 저장), 엑셀·CSV 내려받기.
7. 재검증: 미확인 채널만 대상으로 자막 검색, 남은 영상 분석을 다시 실행한다.

## 3. 구조

```
app/
  main.py        FastAPI 앱, 정적 화면 제공, 보안 헤더
  security.py    토큰 생성·해시, 키 가리기(redact), 입력 검증
  jobs.py        작업 폴더 준비, 하위 프로세스 실행, 상태 갱신
  store.py       SQLite: 작업, 단계 상태, 확인 기록
  estimate.py    영상 분석 대상 수와 예상 비용, 상한에 맞춘 채널당 개수 계산
  results.py     work/ 캐시와 리포트에서 보드용 JSON 만들기
web/             업로드·진행·보드 화면(정적 HTML/JS)
seeding_checker.py   기존 엔진(명령줄·캐시 형식 유지)
tests/
```

**엔진을 하위 프로세스로 실행하는 이유**
엔진은 `work/`, `output/`을 현재 폴더 기준으로 쓰고, 키를 환경변수에서 읽는다. 여러 사용자가 동시에 쓰려면 둘 다 작업별로 분리돼야 한다. 엔진을 고치는 대신 **작업마다 전용 폴더를 만들고, 그 폴더를 현재 폴더로 하여 엔진을 별도 프로세스로 실행**한다. 키는 그 프로세스의 환경변수로만 전달한다. 엔진 코드와 캐시 형식은 바꾸지 않아 1·2차 데이터와 호환된다.

**작업 폴더 `data/jobs/<job_id>/`**
`input.xlsx`, `config.yaml`(사용자 입력으로 생성), `reference/`, `work/`, `output/`, `log.txt`. 키는 어디에도 쓰지 않는다.

## 4. API

| 메서드 경로 | 설명 |
| --- | --- |
| POST /api/job | 엑셀·설정·참고 사진 업로드. 작업 토큰을 한 번만 돌려준다 |
| POST /api/job/prepare | YouTube 키(헤더)로 1단계 시작 |
| GET /api/job | 단계, 진행 상태, 오류, 예상 비용 |
| POST /api/job/analyze | OpenAI 키(헤더)와 상한(USD)으로 2단계 시작 |
| POST /api/job/recheck | 미확인 채널 재검증 시작 |
| GET /api/job/results | 보드용 JSON |
| PUT /api/job/records/{channel_no} | 확인 결과 기록 |
| GET /api/job/log | 가려진 진행 로그 |
| POST /api/job/export | 판정과 확인 기록 CSV |
| DELETE /api/job | 작업과 데이터 즉시 삭제 |

작업 토큰은 **헤더** `X-Job-Token`으로 보낸다(주소 경로에 넣으면 서버·프록시 접근 로그에 남기 때문). 화면 주소에서는 `#/j/<토큰>`처럼 조각(#) 뒤에 두어 서버로 전송되지 않는다.
API 키는 요청 **헤더**(`X-Youtube-Key`, `X-Openai-Key`)로만 받는다. 주소, 쿼리, 본문, 로그에 넣지 않는다.

## 5. 키와 데이터 보안 (핵심)

1. **키 보관**: 키는 요청을 처리하는 동안 메모리에만 있고, 엔진 하위 프로세스의 환경변수로 전달된 뒤 폐기한다. DB, 파일, 로그, 응답에 쓰지 않는다. `.env`는 작업 폴더에 만들지 않는다.
2. **키 가리기**: 엔진이 출력하는 로그에 키가 섞일 수 있다(예: 요청 URL의 `key=` 파라미터가 예외 메시지에 들어가는 경우). 하위 프로세스 출력은 파일에 쓰기 전에 키 값과 `key=…` 패턴을 모두 `***`로 바꾼다. 서버 자체 로그도 같은 처리를 한다.
3. **전송**: 운영에서는 HTTPS만 허용한다(프록시 헤더 확인). 응답에는 `Cache-Control: no-store`를 붙인다.
4. **화면**: 키 입력칸은 `type=password`, `autocomplete=off`. 키를 localStorage나 쿠키에 저장하지 않는다. 페이지를 닫으면 사라진다.
5. **작업 접근**: 작업 주소 토큰은 256비트 난수(`secrets.token_urlsafe(32)`)이며, DB에는 해시만 저장한다. 토큰을 모르면 목록도 볼 수 없다(목록 API 없음). 잘못된 토큰 요청은 속도 제한을 건다.
6. **입력 검증**: 엑셀은 크기(5MB)와 확장자·내용 형식을 검사한다. 참고 사진은 이미지 형식과 개수(최대 30장)·크기(장당 5MB)를 제한하고, 파일명은 서버가 새로 만든다(경로 이탈 방지). 설정은 허용한 항목만 받아 `config.yaml`을 서버가 생성한다.
7. **비용 상한**: 상한 없이는 영상 분석을 시작하지 않는다. 서버 전체 설정으로 상한의 최댓값과 동시 작업 수(기본 1)를 제한한다.
8. **데이터 수명**: 영상 파일은 엔진이 분석 직후 삭제한다. 작업 데이터는 7일 뒤 자동 삭제하고, 사용자가 즉시 삭제할 수도 있다.
9. **개인정보 고지**: 업로드한 리스트에는 제3자(유튜버) 정보가 들어 있으니 서버에 7일 보관되고 삭제할 수 있다는 점을 화면에 알린다.

## 6. 비용 추정과 상한

- 준비 분석 후 `pick_candidates`와 같은 규칙으로 영상 분석 대상(채널×영상)을 센다.
- 영상당 예상 비용 = 설정의 모델 단가와 1차 실행 실측(영상당 약 $0.03)을 기본값으로 한다. 사용자는 단가를 바꿀 수 있다.
- 상한 내에서 채널당 분석 영상 수 k를 가장 크게 잡는다(`max_visual_videos_per_channel`을 작업 설정에서만 낮춤).
- 화면에는 "예상 약 $X, 상한 $Y"를 항상 보여준다. 실제 사용 토큰은 엔진이 끝에 출력하는 요약으로 보고한다.

## 7. 오류 처리

- 단계마다 엔진이 `work/`에 저장하므로 실패해도 같은 단계를 다시 실행하면 이어진다.
- 엔진이 실패하면 종료 코드와 가려진 마지막 로그 줄을 사용자 말투의 메시지로 보여준다(예: 키가 잘못됐을 가능성, 쿼터 소진).
- 서버가 재시작되면 실행 중이던 작업은 `중단됨`으로 표시하고 다시 시작할 수 있게 한다.

## 8. 테스트

- 단위: 토큰 생성·해시, 키 가리기, 입력 검증, 비용 추정, 결과 변환.
- API: 가짜 엔진(키를 받아 짧은 로그를 남기고 끝나는 스크립트)으로 업로드 → 준비 → 상태 → 결과 흐름을 확인한다. **키가 DB·로그·파일·응답 어디에도 남지 않는지** 검사하는 테스트를 포함한다.
- 화면: 브라우저로 업로드와 보드 화면 동작을 확인한다(키 없이, 가짜 데이터).
- 실제 YouTube·OpenAI 호출 테스트는 하지 않는다.

## 9. 배포와 남은 위험

- Dockerfile에 파이썬, ffmpeg, yt-dlp를 포함한다. Railway 배포는 별도 승인 후 한다.
- **영상 다운로드가 클라우드 서버 IP에서 막힐 수 있다.** 배포 전 시험으로 확인하고, 막히면 영상 분석을 사용자 PC용 도구로 분리한다.
- 사용자 키를 받아 서버가 호출하는 서비스의 YouTube·OpenAI 약관 적합성은 공개 전에 확인해야 한다.
- 영상 다운로드(yt-dlp) 자체가 YouTube 약관상 회색지대다.
