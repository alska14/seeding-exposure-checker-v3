## 프로젝트: 시딩 노출 확인 도우미

> 시딩(협찬)한 유튜버가 영상에서 우리 제품을 착용했는지 자동으로 골라주는 웹앱

---

## 1. 목표 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | 시딩(협찬)한 유튜버가 영상에서 우리 제품을 착용했는지 자동으로 골라주는 웹앱 |
| 누구를 위한 것인가 | 한 번에 수십~100명에게 제품을 보내고, 업로드 여부를 일일이 확인해야 하는 의류·뷰티 브랜드의 시딩 담당자 |
| 핵심 기능 3가지 | 1. 시딩 리스트 업로드와 자동 분석 2. 유튜버별 노출 판정과 근거 영상 보드 3. 담당자 확인 결과 기록과 엑셀 내보내기 |
| 완성의 기준 | 실제 시딩 리스트 1개(약 90명)를 업로드해서 결과 보드를 받고, 담당자가 확인 결과를 기록해 엑셀로 내보내기까지 끝낸다 |

## 2. 해결하려는 문제

시딩을 하고 나면 담당자가 유튜버 채널을 하나씩 열어 영상을 훑으며 제품이 나왔는지 확인한다. 93명 기준으로 이 작업은 사람 손으로 하루 이상 걸리고, 어디까지 봤는지 기록도 흩어진다.

이 앱은 사람이 볼 필요가 큰 채널(확인됨·의심)을 먼저 골라서, 담당자의 확인 시간을 줄이는 것이 목적이다. 올리지 않았다는 판단은 하지 않고, 찾지 못한 채널(미확인)은 사람이 확인한다.

## 3. 핵심 기능 3가지

1. **시딩 리스트 업로드와 자동 분석**
   엑셀을 올리면 채널별로 발송일 이후 영상을 모아, 제목·설명란·댓글·자막에서 브랜드 언급을 찾고, 단서가 없는 채널은 영상 장면을 분석한다.
2. **유튜버별 노출 판정과 근거 영상 보드**
   확인됨·의심·미확인으로 나눠서 보여주고, 근거 영상은 제품이 나온 장면의 시점으로 바로 열린다.
3. **담당자 확인 결과 기록과 엑셀 내보내기**
   담당자가 "착용 확인 / 업로드했으나 미착용 / 업로드 안 함 / 확인 불가"를 기록하고, 결과를 엑셀로 내려받는다.

## 4. 이번 버전에서 하지 않는 것

- 인스타그램, 틱톡 등 유튜브 외 채널
- 노출 시간(초)·화면 비중 같은 노출도 지표
- 여러 브랜드·여러 사용자 계정 관리
- 자동 알림과 결제

## 5. 현재까지 만든 것 (2026-11-04 기준)

분석 엔진은 파이썬 프로그램으로 이미 동작한다. 남은 일은 이것을 웹 화면에서 쓸 수 있게 하는 것이다.

| 기능 | 현재 상태 |
| --- | --- |
| 1. 업로드와 자동 분석 | 분석 엔진 완료(명령어로 실행). 웹에서 업로드·실행하는 화면이 남음 |
| 2. 판정 보드 | 엑셀 리포트(요약·영상별·수동확인 목록)로 완료. 웹 보드가 남음 |
| 3. 확인 기록 | 엑셀의 드롭다운으로 임시 구현. 웹 입력·저장이 남음 |

**실제 실행 결과** (시딩 리스트 93명)

- 영상 669개를 약 54분에 분석했고, 비용은 OpenAI 정가 기준 약 $21.5(영상당 약 $0.03)였다.
- 판정은 확인됨 8, 의심 3, 미확인 78, 업로드 없음 3, 채널 오류 1이다. 이 중 새로 찾은 7건(댓글 1, 영상 3, 의심 3)은 사람 확인 대기 중이다.
- 정답을 아는 영상 3개(제품 5개)에서 4개를 찾았고 오탐은 0이었다. 표본이 작은 쉬운 영상이라 전체 정확도는 아직 모른다.

## 6. 구성

| 구분 | 내용 |
| --- | --- |
| 분석 엔진 | 파이썬. YouTube Data API(영상·댓글 수집), 영상 프레임 추출, OpenAI 비전 모델(착용 판단과 반박 검수) |
| 웹 화면 | 업로드, 진행 상황, 결과 보드, 확인 기록 화면 (구현 방식은 Workbench에서 확정) |
| 저장 | 채널별 영상·판정 결과, 담당자 확인 기록 |
| 보안 | API 키는 환경변수로만 두고 코드·제출물에 넣지 않는다 |

## 7. 완성의 기준과 측정 방법

| 기준 | 측정 방법 |
| --- | --- |
| 실제 리스트로 한 번에 완주 | 약 90명 리스트를 업로드해 결과 보드가 나온다 |
| 확인 결과 기록과 내보내기 | 담당자가 최소 20곳의 확인 결과를 기록하고 엑셀로 내려받는다 |
| 정확도 검증 | 도구가 `확인됨`이라 한 건을 사람이 열어 맞은 비율을 기록한다. 놓친 비율은 `미확인` 중 10곳을 사람이 확인해 잰다 |
| 비용·시간 | 전체 실행 시간과 API 비용을 기록한다 |

## 8. 진행 계획

| 점검 단계 | 이 단계에서 끝낼 것 |
| --- | --- |

| 최종 제출 | 실제 리스트로 한 번 완주하고, 사람 확인으로 정확도를 검증한 결과를 정리한다 |

## 9. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 못 찾은 채널이 많음(미확인 78/93) | 미확인은 "안 올림"이 아니라고 화면에 명시하고, 채널 안 브랜드 검색 링크로 사람 확인을 돕는다 |
| 오탐(제품이 아닌데 확인됨) | 반박 검수 단계를 두고, 근거 장면 링크로 사람이 바로 확인한다 |
| YouTube API 일일 쿼터(10,000) | 이미 받은 데이터는 재사용하고, 쿼터가 소진되면 다음 날 이어서 실행한다 |
| 영상 다운로드의 약관 문제 가능성 | 분석 직후 파일을 삭제한다. 서비스로 확대하기 전에 약관을 확인한다 |
| 비용 증가 | 영상 수·기간을 설정으로 제한하고, 실행 끝에 사용 토큰과 예상 비용을 표시한다 |
| 개인정보 | 유튜버 목록과 확인 결과는 외부에 올리지 않고, 제출물에는 집계 수치만 쓴다 |
